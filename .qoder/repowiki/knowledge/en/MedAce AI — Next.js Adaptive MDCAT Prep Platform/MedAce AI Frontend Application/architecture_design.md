The app is organized under the Next.js App Router with `src/app/` holding route segments (auth, dashboard, practice, results, study-plan, profile) that compose reusable layout components from `src/components/layout/` and presentational primitives from `src/components/ui/`. Client-side state and server data are unified through a top-level `Providers.tsx` wrapping every page in a `QueryClientProvider` plus a `ToastProvider`, so all pages share one React Query cache and toast system. Data access is centralized in `src/lib/api-client.ts`, which calls Next.js Server Routes under `src/app/api/` (`/api/quiz/*`, `/api/dashboard/stats`, `/api/study-plan/generate`) — pages never call Supabase or AI APIs directly, only via this typed client. Route-level protection is declared in `src/middleware.ts` against a `protectedRoutes` list, with Supabase cookie checks stubbed for future integration. Shared domain types live in `src/types/quiz.ts` and are consumed by both the API client and pages, keeping the contract between server routes and client code consistent.
